# 07 — The buttons you already own

**Platform:** Windows x64  
**Time:** about 10 minutes  
**Cost:** nothing if your mouse already has spare buttons

This is the first hardware stage. Your right hand already moves between windows with the mouse; a spare thumb button can remove the trip back to the keyboard for the actions you repeat most.

## Map a three-button mouse

Open your mouse manufacturer's configuration app and assign:

| Mouse button        | Keystroke to send | Handy action        |
| ------------------- | ----------------- | ------------------- |
| Thumb 1             | `ctrl+space`      | Transcribe toggle   |
| Thumb 2             | `ctrl+alt+s`      | Transcribe & Submit |
| Thumb 3, if present | `escape`          | Cancel              |

Use a global profile if these buttons are otherwise unused. Use per-application profiles when your editor, browser, or game already assigns them. A conflict can make both actions fire or let the other application win; [A hotkey another app already owns](../features.md#a-hotkey-another-app-already-owns) is the symptom index for Handy's side of that collision.

Most mouse software emits a tap, not a held key. Map the Transcribe toggle shown above, not push-to-talk. Use push-to-talk only if the mouse software provides separate press and release actions and you verify both.

Test all mapped buttons in a blank Notepad document. The win is small but physical: the hand already aiming the pointer can start, finish, submit, or cancel without finding a chord.

If your mouse has no spare buttons, skip this stage. The keyboard shortcuts you set in stage 04 are the complete product; nothing later depends on a mapped mouse.
